# Demo script — ready before UI implementation

Purpose: learn whether an insights buyer values competitive decisions with inspectable evidence. All figures are generated and fictional. Read actual fixture values from the app; never memorize the old million-review claims.

## Preflight

Open /demo/ready with a fresh demo profile. Choose saved view “TOZO competitive exposure” (Wireless Earphones, all sources, Unique, full window; TOZO vs Apple/Sony/JLab/Jabra). Confirm Radar shows supported Ergonomics exposure. Open an excerpt, change a source filter, export one brief. Keep “Restore demo scenario” available. Do not reset a prospect's local work without warning.

## Ninety seconds

| Time | Screen/action | Say |
|---|---|---|
| 0–15s | /switch-radar | “This is synthetic data illustrating the workflow. We want to see where competitors outperform us on attributes reviewers discuss.” |
| 15–35s | Expand Ergonomics exposure | “Here is the gap, the size of the evidence base, and which competitor is ahead in this scenario.” |
| 35–55s | Open one excerpt per side | “We can inspect both sides. These examples illustrate the comparison; they are not proof of customer switching.” |
| 55–75s | Draft next step | “The output is a testable product or messaging hypothesis, with an owner and a measure of success.” |
| 75–90s | Print executive brief | “This is what your team can review and act on.” |

## Eight-minute tour

1. /demo/ready → /switch-radar: explain the competitive question and synthetic scope.
2. Change the focal selector; return to TOZO scenario. Show that the subject is explicit.
3. Exposure → /comparison: compare gaps, topic-review n and the inclusive category benchmark.
4. Ergonomics → evidence drawer: read full context; inspect both sides.
5. /topics/audio-quality on TOZO T10: use mixed-review fixture. Explain why stars and individual opinions differ. Do not use the intentionally incorrect QA fixture as evidence of good classification.
6. September/October saved monthly scope: show the change and its support counts; distinguish change in review opinions from measured lost buyers.
7. Show a low-support filter: “We decline to rank when evidence is too thin.”
8. Save view, draft hypothesis, download Excel; show filter/methodology cover.
9. If PowerPoint phase is complete, export deck. Otherwise use the already complete print brief.
10. Optional setup preview: choose US versus US+Canada and show actual counts change. Skip billing unless asked about packaging.

## Recovery moves

Missing finding → restore canonical scenario; do not invent a result. Load error → Retry; then /demo/ready to a new fictional profile. Export failure → retry frozen snapshot; print brief remains available. Missing shared local group → explicitly restore seeded baseline, never pretend identical state.

## Questions to answer candidly

“Why does data stop in 2021?” — “The concept uses a fixed historical synthetic scenario so demonstrations are reproducible. Live refresh remains future work.”

“Does this show people switching brands?” — “No. It shows opinion differences and hypotheses. A future decision-evidence layer would need explicit switch reports or verified outcomes.”

“Are these real consumer quotes?” — “No, these are authored examples. The demo proves navigation and calculations, not collection or classification quality.”

“Is this available for our category?” — “Only audio is included here. Coverage and commercial terms need validation.”

“Is it already integrated with Stagwell systems?” — “This frontend has no live integrations.”

## Evaluation notes

After each of five proposed buyer sessions, record role/category, current workaround, first useful finding, time to first evidence, whether the next step feels actionable, whether they request the brief, and willingness to pilot at a stated price. No runtime analytics required; use facilitator notes. A go/no-go threshold is in release-gates.md.
